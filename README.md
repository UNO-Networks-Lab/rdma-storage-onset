# A Sharp but Configuration-Dependent Loss-Recovery Onset in Closed-Loop RDMA Storage Fabrics — artifact

Code and analysis for the paper of the same title by Haoyu Wang, Bang Tran,
Peng Jiang and Xiaoqian Zhang (submitted to ICNC 2027).

Every table in the paper is regenerated by one script, `plot_boundary.py`,
directly from the raw per-operation logs. The raw logs are too large for git
(about 2 GB) and are archived separately on Zenodo.

## Contents

| Path | What it is |
|---|---|
| `hw-cas/cas_gate.c` | The io_uring admission gate every experiment runs. One binary; arms differ only in the admission bound `k` and in what sets it. |
| `hw-cas/run-*.sh` | Campaign drivers. Each takes an output directory and writes one sub-directory per run. |
| `hw-cas/incast-setup.sh` | Idempotent bring-up of an N:1 NVMe-oF testbed on a live CloudLab experiment. |
| `hw-cas/sample-counters.sh`, `hw-cas/analyze-*.py` | NIC hardware-counter sampling and per-campaign analysis. |
| `cloudlab/profile-incast.py` | CloudLab profile: one target plus N initiators, all on one switch. |
| `cloudlab/scripts/` | Node setup: NVMe-oF target (`null_blk` over `nvmet-rdma`), initiator connect, RoCE inspection, telemetry. |
| `plot_boundary.py` | Regenerates every table and figure from `data/testbed/`. |

## Data

Download `dsscc-icnc-data.tar.gz` (619 MB) from Zenodo,
[doi:10.5281/zenodo.22838017](https://doi.org/10.5281/zenodo.22838017), and unpack
it so that the run directories sit under `data/testbed/`:

```bash
mkdir -p data && tar -xzf dsscc-icnc-data.tar.gz -C data
(cd data && sha256sum -c --quiet SHA256SUMS) && echo verified
```

`data/` is git-ignored.

## Regenerating the tables and figures

```bash
pip install matplotlib
PAPER_DIR=out python3 plot_boundary.py
```

Tables are written to `out/tables/` and figures to `out/figs/`. The analysis
asserts that every arm of a comparison did identical work, and refuses to
emit a table otherwise.

## Running the experiments

The measurements used CloudLab `c6525-25g` nodes (ConnectX-5, 25 GbE) with all
nodes on one switch, so the target-facing egress port is the single congestion
point. That placement is load-bearing: results from a topology with more than
one congestion point are not comparable.

```bash
export USER_CL=<your CloudLab username>
export KEY=~/.ssh/<your CloudLab key>
hw-cas/incast-setup.sh <experiment-hostname-suffix> 3
KLIST="1 2 4" SEED=example hw-cas/run-makespan.sh <suffix> data/testbed/my-run 3 4194304 3800 12
```

The drivers stop if `USER_CL` is unset rather than guessing an account. Runs
are written as `<arm>_r<rep>/`; campaigns with randomised arm order also write
`arm_order.txt`, which the analysis uses to test whether run position predicts
the outcome.
